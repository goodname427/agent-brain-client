# Agent Brain 产品 4.0 封板

本次固定产品 4.0 基线，Client 运行包仍为 **0.4.8**。产品编号、独立组件提交和已安装运行包分别记录在 [FREEZE-4.0.json](../FREEZE-4.0.json)；不把 main、源码 tag 或产品编号当成已安装客户端的更新渠道。

## 本版范围

- Memory / Rule / Skill 的既有授权管理与跨会话存查。
- 在用户明确批准的来源内默认跨项目检索，按当前问题与保留的来源判断相关性；不要求逐条标记全局，其他项目的规则不能自动成为当前项目或全局规则。
- 支持官方 Hook 的本地 Codex 工作流中采集未来轮次、经现有服务和已配置模型提取，并在提问时召回；不补扫原生历史或聊天数据库。
- 受控 outbox、离线恢复、原请求幂等与不确定任务保护；服务启动、恢复开启及提交事件唤醒同一常驻恢复消费者。
- 原有模型累计账本和用户费用选择保留，不自动充值。秘密、LocalOnly 与明确禁止共享限制继续有效。

已包含的收尾修复：后台 GitHub 备份有独立且有上限的网络等待；持久提取以实际获准会话任务键核对原 batch pin；启动消费者恢复已登记、当前仍获准且未关闭的队列。没有增加数据接收方或凭据权限。

## 支持边界与证据

当前交付面向 macOS arm64 上支持官方 Hook 的本地工作流。宿主须正常加载并审阅当前 Hook 定义；云端编排不会因有本地工具访问而执行本地命令 Hook。其他设备不自动继承来源批准。Windows 与 DeepSeek Harness 留待下一产品阶段，本次没有开始实现。

源码 CI、精确部署健康以及已有获准队列的正常处理记录作为封板证据；这不是全部宿主、设备、离线冲突或模型内容正确性的完整验收。部署与私人数据证据由所有者保存，不放入公开发布材料。新安装仍须明确来源授权，封板本身不会开启未知来源。

## 升级

1. 保留当前配置、凭据引用、源批准、Data、Core 状态、模型账本及未确认队列。源码目录有本地修改时先保留修改，不强制覆盖。
2. Client 使用原受信政策指定的渠道：`sh tools/install-mac.sh --action check-update`，再执行 `sh tools/install-mac.sh --action update`。查看 active package 与实际 MCP worker 版本的区别；按宿主正常方式重载或新开会话，不终止在途工作。源码全局入口更新使用 `sh tools/memory.sh global-install`，保留原来源选择、其他 Hook 与 MCP 注册，不绕过原生信任。
3. Server 仅安装由干净提交生成的服务包。沿用现有部署流程，核对当前入口、所有 memory/global 参数及私密文件摘要，等待 Data 和 native request 锁中的在途工作结束，备份后只切换服务代码入口，再核对运行提交、服务健康和消费者状态。
4. 不以升级为由新增测试聊天、模型探针、历史导入或重置用量。现有获准队列由正常消费者处理，`succeeded` 与 `no-facts` 都是处理终态；`staged`、`running`、`review-required` 不作为完成。

## 回滚与恢复

Client 的既有 ReleaseEngine 在更新中断或预检／健康检查失败时，使用已记录的 snapshot、before pointer 和 journal 自动恢复。没有公开的任意版本一键降级入口；不要手改 active.json、政策摘要、信任锚或把 tag 换成安装渠道来绕过版本检查。需要回退修复时，在原获准渠道发布兼容的向前修复，保留已验证包和原 journal。

Server 代码回退使用现有部署回执中的精确前像；受控降级备用提交为 `fe41753da518d6335c0ea0691ea1e7b940de66ef`。先按既有接口关闭自动处理、等待在途 native/Data 工作结束，备份最新 Data、独立 Core/receipt 状态、政策和账本；比较当前 unit/参数/摘要后，仅恢复已验证的旧代码入口和必要的同版 unit 前像，保留现有身份与已授权参数，再核对健康。未知并发变动须先处理，不能覆盖。

**回滚代码不恢复旧 Data、不倒退 cursor、不删除 outbox、请求／提取回执或模型账本。** 上述备用代码没有启动恢复消费者，因此回退会降低无人值守恢复能力；保持来源关闭直到恢复策略明确，优先修复并回到封板实现。恢复来源时保留原请求身份，不盲重试不确定模型任务。
