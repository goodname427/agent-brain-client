# 集合快照容量

> 当前维护；适用：共用 Client 内容快照、原生映射与事务恢复。

`content_catalog` 允许最多 256 条记录，每条编码后的内容记录最多 65,536 字节。
原实现另外把整份快照和全部映射限制为 512 KiB，快照文件限制为 1 MiB，
事务日志限制为 3 MiB。合法的多条记录组成的集合因此可能在 Server 保存成功后
返回 `remote-snapshot / validation-failed`；放宽第一处限制还会在持久化、离线读取
或回滚时遇到下一处限制。

集合快照现在按 `256 × (65,536 + 512)` 字节限制，512 字节覆盖每条记录的
协议包络。在线获取、增量缓存复用、快照文件读写与离线读取采用同一上限。
映射预算覆盖 Rule 正文在单独文件与常驻 AGENTS 块中的重复，以及原有原生文件
前像；事务预算覆盖 base64 前像、目标、Windows 中断恢复图像和路径／摘要元数据。
新旧事务日志使用相同读写上限，既有日志与快照格式兼容，无需迁移。

单条记录、目录数量、身份与 scope、来源／离线绑定、摘要、目录变更检测、原生
单文件限制和外部修改保护继续核验。outbox、导入账本等其他文件的容量不变。
超出集合持久化容量时返回固定的 `collection-capacity-exceeded`，不输出正文、
路径、凭据或异常文本。Server 保存回执仍独立于本地映射结果。

`test_content_write_failures.CollectionCapacity` 使用隔离合成目录验证超过 1 MiB 的集合、
保存回执、增量复用、离线读取、超过 3 MiB 的日志、持久化失败回滚，以及退出后
重启恢复；同时验证超长记录和超过 256 条的目录仍保留原映射。
Mac 全量回归和 Windows Python 3.11／3.13 CI 运行这些用例。CI 不替代已安装
设备的升级验收；开发测试不重发或清理任何真实待发送记录。
