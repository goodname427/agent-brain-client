# AB 开发与交付规范

## 做最短可靠的方案

- 能删的门槛就删，能复用就不加。不要因假设风险新增确认、重复认证、限次、预检或阻塞。确需保留的检查应对应具体问题，范围收在实际受影响的路径。
- 保留必要的账号、权限、数据完整性与回退保护。不为通过检查绕过这些保护，也不擅自关闭、限制或不启用用户要求的功能。
- 优先修导致失败的行为，不用新检查给旧流程兜底。正常路径不受无关外部信息影响；真实错误要说明卡在哪一步。

## 规划、并行和交接

- 一个独立任务一个清楚的上下文。对用户可见的开发默认用独立 Mac Codex 对话；同一任务的修复和复验回原对话，不能拿另一个任务的上下文凑合。开发、审查或验证可并行，但同一工作区避免多个写者。
- 开工前找与本任务相关的已有设计、约束和失败记录，把关键内容带进派工。做完子任务须继续下一步能独立完成的工作，不把原型、PR 或一次检查当成最终交付。
- 汇报说问题、证据、处理结果和剩余影响，区分本地验证、合入、发版、部署与实机回归。主负责 Agent 核对每次交接是否多加门槛、漏了公共影响、验错路径或停在半途；能接着推进就直接做，确需用户操作才标【需要处理】。不用为此另填表。

## 工单和交付状态

- 一个任务在对应仓库只开一个 Issue。边界确定后先开单，创建时一次填齐原生 Type（工作类型）、Milestone（计划交付的版本或文档批次）、一个 `状态:` 标签和实际改动涉及的 `模块:` 标签。模块可多选，仅跨模块测试不加模块标签。纯文档合入 `main` 即交付，可用独立文档里程碑，不挂到已发布的软件版本。建单后逐项读回标题、范围、验收标准和上述字段，核对后再派工。
- 每个 Issue 始终保留一个 `状态:` 标签，按实际进度在 `待开发`、`开发中`、`待合入`、`待发布`、`待验收`、`已完成` 间切换，跳过不适用的阶段。需生产验收的 Server 工单在 GitHub 发包后标 `待上线`，实际部署并在生产读回确认后才标 `待验收`；纯发包或 CI 工单跳过上线。评估后暂不做的工单标 `挂起`，记录原因并保持开放，恢复时改回 `待开发`。
- PR 正文用 `Tracks #<编号>` 关联工单，避免合入自动关单。软件发版前按 Milestone 核对范围内的改动都已进入 `main`。AB 发版请求默认涵盖发包和适用的 Server 生产上线。用户明确只发包或暂缓上线时，按指定范围执行。生产操作以用户明确授权为准。
- 合入、发包、上线或验收一旦实际发生，先在原 Issue 同步状态和对应证据，再读回核对，之后才汇报或安排下一步。记录对应的 PR／`main` 提交、GitHub Release 与实际版本、生产读回或验收结果。Client Release、`stable` 渠道和 Server 生产上线分别留证，本地验证和实机验证也各自留证。
- 需用户实测时，明确由用户验收，给出操作步骤和通过标准。验收通过后先换成 `已完成`，再关闭 Issue。发包、取消或归档都不算完成。状态以标签为准，证据记在原 Issue，沿用现有审批。

## 验证和发版

- 先验用户实际会走的路径，典型历史状态、失败恢复和回退按改动范围覆盖。日常 PR 只跑既有快速阻塞检查，完整自动化验证留给已有发布流程；不要新增一刀切的检查、人工审批或重复全量。
- 工程侧交付可安装或可回归的版本和最短步骤。真实用户设备和实际宿主由用户验收，不把它当发布前置；隔离、模拟和未运行的项目都如实标注。
- Client 和 Server 独立编号；常规小修用补丁号，升次版本前先说明。不要让无关或尚未定位的问题阻塞能交付的修复。远端 CI 不可用时走既有本地路径，不把本地结果说成远端通过。发布和生产部署需分别核实。

## 文档是交付的一部分

- 根 `AGENTS.md` 只留开工要记住的行为和索引。这一页维护常用开发规范，具体步骤放在对应流程文档，按主题持续修订。
- 定下来的设计写清适用范围、选择理由和取舍；反复发生或代价高的故障写清触发条件、已确认原因、最小预防办法。未证实的原因保留为假设。
- 优先补在既有流程说明或回归用例附近，不为每个小改动另写一篇。下次相关任务先读这些记录，收尾核对是否真的防住；不另加报告或审批环节。

## Client 约定和已知教训

- 通用问题在公共层修。只有证据明确是宿主独有，才只改该宿主；否则考虑 Codex、CodeBuddy、Mac 和 Windows，不复制一套实现。
- 不为旧清单把普通功能塞回旧模块，也不长期保留旧入口。打包清单有变化才提前用当前稳定版核对升级路径；没有变化不额外检查。0.8.22 到 0.8.23 只增加普通模块，旧清单仍要求文件名完全一致；该版选择官方重装，不代表以后都要重装。
- 重装的设计目标是先准备新版、确认能连接原账号，再切换入口；已有事务只续接，不重复认证或归档。曾有旧 `.codex` 事务被新 `shared-native` 路径错误拒绝。修改续接时验证同一事务能走到入口恢复，不用手工删除目录。具体操作见[重装流程](../installation/reinstall.md)。
- 已在使用的 MCP 运行内容没变就不重连；确有改动，也以正常更新免手动重连为目标，并保留已接收请求的结果。这是设计要求，不是已发布能力。
- 发布与回退入口见[发布流程](release-pipeline.md)，公共层边界见[运行代码结构](architecture.md)。
